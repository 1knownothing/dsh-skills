# references/artifacts.md — 产物模板

> `.agent/<task-slug>/` 下的 8 份文件模板。小任务只留 `spec.md` + `verify.md`。
> 项目已有同类约定（如 `docs/NN-*.md` 编号文档）时**服从项目约定**，这里只定义"信息必须齐全"。

## evidence.md（S5）

```markdown
# 实现证据

### 2026-10-09 14:20 — T1
$ <命令>
<原始输出，不转述>

$ <命令>
<原始输出>

备注：<遇到的意外 + 处理方式>

### 2026-10-09 14:55 — T2
$ <命令>
<原始输出>
```

**禁止**：写"输出正常"、"测试通过"而不贴输出；写没跑过的命令。

## verify.md（S6）

见 `references/verification.md` §6 的完整格式。要点：
- 四层 L1–L4 分段，每段 `$ 命令` + 原始输出
- 逐条 AC 判定（✅/❌/⚠️未验证）
- 反向对照记录（破坏了什么 → 哪个断言变红）
- 最可能挂的 3 个场景
- 失败分类（A–E）

## 关于 `.agent/` 目录

- 若项目已忽略 `.agent/`，直接用
- 否则建议加入 `.gitignore`（这些是**过程产物**，不是交付物）
- 但 `lessons.md` 的可执行部分（校验脚本/测试）**必须进版本控制**
- 项目有更强约定时（例如本项目要求文档进 `docs/NN-*.md` 并编号），**以项目约定为准**
