# 通用 Agent 开发流程（agent-dev-workflow）

一句话原则：**先明确"什么算做完了"，再动手；写完的人不许自己验；没通过就分类重试，超限就升级给人。**

这不是建议，是本次任务的执行协议。除非用户明确说"只要草稿/快速试一下"，否则按阶段推进，每阶段**必须留下产物**。

---

## 前言：这套流程的证据基础（哪些有实证、哪些是工程判断）

**诚实标注，防止把"听起来合理"当成"已验证有效"。**

**有实证支撑（可放心依赖）：**

| 机制 | 证据 |
|---|---|
| **独立验证者（S6）** | 最强的一条。ICLR 2025 对照实验：self-critique 出现显著性能崩溃；sound external verifier 显著增益；**仅仅"可信验证者 + 重试"就保留了大部分收益**。 |
| **上下文外部化、阶段间只传最小产物** | 长上下文性能随输入增长而下降（Context Rot，18 模型）；相关信息在中间时性能显著下降（Lost in the Middle）。 |
| **固定阶段流水线优于自由路由** | 简单三阶段流水线（localization→repair→validation）在 SWE-bench Lite 上以最低成本取得当时最高分，超过所有开源 agent；7 个 SOTA 多智能体系统实测失败率 41%–86.7%。 |
| **S2 只读勘查** | 有对照收益但**很小**（LLM-judge 1–5 分 +0.15，SWE-bench Lite +1.7%）。值得做，别宣称大收益。 |

**有机制支持、但无效果量证据（当"风险缓解"，别当"已验证"）：**
- 编译/静态门禁、dry run、（本项目里对应）审计脚本门槛
- 自愈重试循环
- 人工否决 → 固化成可重放校验（有官方做法，无效果量）
- **本 skill 里"重试 3 次后升级"的具体次数 = 工程设定，不是实证结论。** 可按任务调整。

**已被否证 / 不要写成收益（黑名单）：**

| 说法 | 事实 |
|---|---|
| "先写 spec 就少 bug" | 89,599 个 PR、119 个仓库的**零结果**：spec 存在与质量**与缺陷结果无关**。→ **spec 的价值是"可审查/可回滚/可交接"，不是"降缺陷"。** |
| "生成即可运行 / 生成即可验证" | 有反面证据：LLM 生成的测试 oracle 主要捕捉"程序实际行为"而非"期望行为"，bug 检出能力天生受限；浏览器自动化定位器会绑定运行期动态数据。 |
| "多智能体必然更强" | 多智能体通常多耗 3–10 倍 token；编码任务可并行度低于研究任务；有团队建数月复杂架构后发现"改好单智能体提示词就够了"。 |
| "测试通过 = 代码正确" | 测试通过只证明**代码与测试自洽**，不证明符合意图。这正是不许自证清白的原因。 |
| "覆盖率门槛保证质量" | **证据缺口**，没有找到支撑。 |

**两条直接来自官方文档的硬约束（已写进本流程）：**
1. 子 Agent 只回传"最终消息"会丢结果，且其内部状态**无法被外层静态读取** → 所以**状态必须落到文件/产物**，不能靠对话传递，也不能靠"我去问它"。
2. 人工介入点恢复时**节点会从函数头整体重跑**（不是从断点那一行继续）→ 所以**人工审查前的副作用必须幂等**，否则会重复写库/重复追加日志。

## 1. 什么时候用 / 不用

**用**：实现功能、改 bug、重构、加脚本、写插件/skill、做数据处理、搭系统、交付文档产物。
**不用**：纯问答、纯解释、无产出的讨论。用户说"先别改，只评估"时，只跑 S1–S3，不碰文件。

**规模裁剪**：任务小（改一个函数、一条配置）时把 S1–S4 压成几行内联说明即可；**S6 独立验证与 S7 验收不可省**。规模越大越不能省前面的阶段。

## 2. 流水线总览

| 阶段 | 名称 | 进入门（不满足就先补） | 产物 | 出门门 |
|---|---|---|---|---|
| S1 | 需求澄清与验收定义 | 有一句可复述的目标 | `spec.md` | 验收标准可判真假；范围外事项写明 |
| S2 | 现状勘查（读代码） | S1 出门 | `survey.md` | 关键结论都带 文件:行号 |
| S3 | 设计与决策 | S2 出门 | `design.md` | 每个方案分叉都有取舍理由 |
| S4 | 任务切片 | S3 出门 | `tasks.md` | 每片有独立验收与写入范围 |
| S5 | 实现 | S4 出门 | 代码改动 + `evidence.md` | 本地自测通过，不造假 |
| S6 | 独立验证 | S5 出门 | `verify.md` | 验收命令逐条实跑，附原始输出 |
| S7 | 审查与验收 | S6 全绿 | `acceptance.md` | 对照 S1 标准逐条判定 |
| S8 | 固化教训 | S7 出门 | `lessons.md` / 项目 `DEVELOPMENT.md` | 人类否决项已变成可重放校验 |

**主路径 S1 → S5 是严格的单向门禁（不许跳过门禁往下走）；唯一的回流是 S6/S7 失败后按第 5 节做分类回流 —— 那是有记录、有理由的受控回退，不是随便回头。**

## 3. 各阶段要点
### S1 需求澄清与验收定义
- 把用户的话**翻译成可判真假的验收标准**。禁止把"更好用"、"优化一下"、"智能一点"直接当标准。
- 每条标准形如：`给定 <输入>，执行 <命令>，期望 <可观察结果>`。判不了的，先拆到能判（拆成数量、时长、通过/失败、文件存在、字段相等）。
- 明确写出**范围外**（这次不做什么），防止范围膨胀。
- 有 3 个以上合理解释时，用 `ask_user_question` 问，问**选择题**不问作文题。
- 落盘到 `.agent/<task-slug>/spec.md`。

### S2 现状勘查
- **先读再写**。用 grep/glob/read 找到真正的接线处，而不是猜。
- 结论必须带 `文件:行号`。写不出行号，说明还没查到，不算结论。
- 查清 3 件事：现有实现长什么样、谁在调用它、改了会连带影响谁。
- 已有可直接复用的函数/模式**优先复用**，不许平行造第二套。

### S3 设计与决策
- **先明确 spec 的价值定位**：它的作用不是"降缺陷"（大样本研究是零结果），而是**可审查、可回滚、可交接**。所以写的是"决策与取舍"，不是"文档仪式"。
- 至少给 2 个方案（含"最小改动方案"），列代价、风险、可回退性，然后**明确选一个并说为什么**。
- 涉及公开接口、数据结构、配置格式、迁移的，必须写清向后兼容策略与失败降级。
- 明确**边界与失败模式**：空输入、大输入、并发、超时、权限、断网、程序被杀。
- **不许在 S3 里改文件。**

### S4 任务切片
- 每片是**可独立验收的最小改动单元**，带：目标、写入范围（哪些文件/目录）、验收方式、依赖关系。
- 写入范围重叠的片**不能并行**，必须串行或换切法。
- 多 Agent 并行时：每片指定唯一 owner，写作用域互斥，依赖用阻塞关系表达而不是靠"我等它"。

### S5 实现
- 一次只做一片，做完立刻跑该片自己的验收命令。
- **改动最小化**：不改与目标无关的代码；不顺手重构；不删除看不懂的东西，先问。
- 发现的既有问题：**记进 `lessons.md` 或待办，不夹带修**，除非它就是本次目标。
- 每步留证据（命令 + 真实输出片段）到 `evidence.md`。**禁止编造输出**；没跑过就写"未验证"。

### S6 独立验证（写的人不验自己的）
- 这是**整套流程里实证最强的一条机制**（见前言），不许省。
- 换一个**独立执行者**（子 Agent 或新会话），只给它：S1 的验收标准 + 产物位置，**不给**实现者的自我评价。
- 按第 4 节四层验证逐层跑，**逐条附原始输出**。
- 验证者的职责是**找反例**：谁会挂？什么输入会挂？改坏了什么？不是确认"看起来没问题"。
- 允许并要求**反向对照**：故意破坏一处，断言必须变红；不会变红说明测试是装饰。

### S7 审查与验收
- 对照 S1 标准**逐条**判定，且必须给**显式裁决态**：`verified` / `partial` / `failed`。
  **"未验证"不等于"修好了"** —— 缺验证就是失败态，不许算通过。
- 检查 diff 是否只有预期改动；检查是否有遗留调试代码、临时文件、被注释掉的代码、密钥。
- 未验证项**必须显式列出**，不许用"应该没问题"结案。
- 面向用户的交付说明：做了什么、怎么验证、已知限制、下一步建议。

### S8 固化教训
- 人类否决 / 验收失败的原因，**写回项目级 `DEVELOPMENT.md`**（或项目既有约定文件），变成下次开工必读的规则。
- 能变成自动检查的，就写成**可重放校验**（测试、审计脚本、断言），而不是只留一句话。
- 项目级文件只在**确实有新教训**时改；不准为了"留痕"灌水。

## 4. 验证四层（S6 必跑，从上到下）

| 层 | 查什么 | 通过标志 | 备注 |
|---|---|---|---|
| L1 静态 | 语法/编译/lint/类型/格式 | 命令退出码 0 | 编译都过不了，后面全没意义 |
| L2 单元 | 目标函数/模块行为 | 相关测试全绿 | 新增行为要新增断言 |
| L3 端到端 | 真实入口跑通 | 有真实运行产物（日志/文件/截图/退出码） | 只跑 mock 不算 |
| L4 验收 | 对照 S1 标准 | 逐条可判真假的结果 | **必须引用真实产物路径** |

**只看"测试通过"不够**：要问"这个测试**有没有可能红**"。永远为绿的测试等于没有测试。

---

## 5. 失败分流（S6/S7 红了怎么办）

先分类，再决定动作。**不同的红走不同的路，不许一律"再试一次"。**

| 失败类别 | 典型现象 | 正确动作 | 禁止 |
|---|---|---|---|
| A 环境/依赖 | 命令找不到、依赖缺失、权限、端口占用 | 修环境后重跑同一命令 | 改代码去迁就坏环境 |
| B 规格歧义 | 实现和验收标准对不上，但代码没错 | 回到 S1 改标准并说明 | 偷偷放宽标准让测试过 |
| C 实现缺陷 | 断言失败、边界没处理 | 回 S5 改实现，**加一条回归断言** | 只改测试不改代码 |
| D 设计缺陷 | 补丁越打越乱、根因在结构 | 回 S3/S4 重新切分 | 继续在错结构上打补丁 |
| E 验证本身错 | 测试写错、断言过严、夹具不对 | 修验证并说明为什么 | 直接删掉碍事的测试 |

**重试上限**：同一失败类别超过 3 次仍未过，**停止自动重试，升级给用户**，说明：试了什么、每次的真实报错、卡在哪、给出 2–3 个可选方向。**打转比失败更贵。**

## 6. 硬约束（违反即返工）

1. **不许自证清白**：实现者不能同时是唯一的验收者。
2. **不许编造证据**：没跑过的命令不许写"已通过"；输出必须来自真实执行。
3. **不许偷偷放宽验收标准**：标准只能通过 S1 显式修订，且要写明原因。
4. **不许静默丢信息**：数据裁剪、异常吞掉、失败转默认值，都必须**显式报告**。
5. **不许无差别报警**：没有真实问题时不许刷"已完成/无异常"式日志。
6. **不许范围膨胀**：S1 写了"范围外"的，这次就不做。
7. **改动必须可回退**：大改动前先确认有版本控制或备份点。
8. **人工审查点之前不许有非幂等副作用**：介入点恢复时会重跑该环节 —— 写库、追加日志、发消息、扣费、删文件这类操作必须在人工确认**之后**，或做成幂等。
9. **不确定就说不确定**：区分"已验证"与"我的推断"，不许混着讲。

## 7. 产物落盘约定

```
.agent/<task-slug>/
  spec.md          # S1：目标、验收标准、范围外
  survey.md        # S2：现状 + 文件:行号
  design.md        # S3：方案对比、选定理由、失败模式
  tasks.md         # S4：切片、写入范围、依赖、验收方式
  evidence.md      # S5：每步命令 + 真实输出
  verify.md        # S6：四层验证结果 + 原始输出
  acceptance.md    # S7：对照 S1 逐条判定
  lessons.md       # S8：教训与新增校验
```

- `.agent/` 若已被项目忽略则直接用；否则建议加入忽略，**不要把它当交付物提交**。
- 项目已有同类约定（如 `docs/` 编号文档、`DEVELOPMENT.md`）时，**服从项目既有约定**，并在 `spec.md` 里注明映射关系。
- 小任务可以只留 `spec.md` + `verify.md`。

## 8. 在 DSH 里怎么落地（harness 映射）

- **本 skill 就是"主管（Supervisor）"**：由你（当前会话的 Agent）读它并逐阶段执行。**不要再实现一层 agent 调度器** —— 平台已经提供编排原语，自己造循环只会多一层不可观测的失败点。
  > 这个方向有官方证据支持：LangGraph 的 `langgraph-supervisor` 包**已停止维护**、官方给出迁移指南；官方文档明文承认 subagent 状态**无法被外层静态发现**（`get_state` 读不到），且 subagent 只回传最终消息、容易丢结果。
- **S6 独立验证** → 用 `subagent` 起一个全新上下文的验证者，只喂验收标准与产物位置；或开新会话。
- **并行切片** → 用 `Agent Teams`（`spawn_teammate` + 共享任务板）：每片一个 owner、写作用域互斥、依赖用 `blocked_by` 表达。
- **批量独立扇出**（审计 N 个文件、迁移 N 处、多角度调研）→ 用 `workflow` 脚本，不逐个手动委派。
- **S1 的歧义** → `ask_user_question`；**S8 的教训** → 项目级 `DEVELOPMENT.md` + 可重放校验脚本。
- **长任务** → `create_goal` 让目标跨轮次保持；阶段状态写进 `.agent/<task-slug>/`，不靠会话记忆。

### 8.1 DSH 安装与可见性（已实测，非推断）

| 事实 | 结论 |
|---|---|
| 安装位置 | `<DSH_HOME>/skills/<任意目录名>/SKILL.md`（本机 = `C:\Users\17835\.dsh\skills\`），即文件系统 provider 的 **user-dsh 根（rank 400）** |
| 是否要改配置 | **不用**。不用改 `cordis.yml` / `cordis.patch.yml`，不用重启 |
| 生效时机 | 有 watcher，**无需重启**：新增/改名/删除/改 frontmatter 都会让下一步的目录刷新（编辑 `references/` 等资源**不会**触发刷新） |
| 是否跨项目 | **是**。user-dsh 根与 `cwd` 无关；project 根只影响遮蔽优先级 |
| 目录名 vs `name` | **两者独立**，目录名不必等于 frontmatter 的 `name`；但 `name` 必须全局唯一 |
| 遮蔽优先级（小者胜） | project-dsh(100) < project-agents(200) < runtime(250) < custom(300) < **user-dsh(400)** < user-agents(500) < bundled(600) |
| 资源引用写法 | **用相对路径**。加载时会注入 `Base directory for this skill: <绝对路径>` 并提示按基目录解析；**没有 `SKILL_PATH` 这类环境变量**（脚本自身用 `$PSScriptRoot` / `$0` 定位） |
| 发现深度 | 只认 `<根>/<目录>/SKILL.md` 与 `<根>/<名>.md`，**不递归**；`references/`、`scripts/`、`assets/` 不会被误当成 skill |
| `description` 上限 | 解析期无上限，但**面向模型的目录会截断到 500 个字符**（UTF-16 单元，汉字算 1）。**触发词必须写进 `description`** —— `whenToUse` 会被解析但当前不参与渲染 |
| 已知边界 | **`minimal` preset 根本不挂 skill-filesystem** → 该 preset 下看不到本 skill。`standard` / `ptc` / `cordis` 可见（本机默认 `standard`） |

### 8.2 本 skill 的安装/更新方式

**改完源文件后跑这一条就够**（重装 + 逐文件哈希校验 + frontmatter 校验 + description 长度检查）：

```powershell
& "D:\1Anewproject\dev\dsh-skills\sync.ps1"            # 重装并校验：退出码 0 = 部署与源字节一致
& "D:\1Anewproject\dev\dsh-skills\sync.ps1" -CheckOnly # 只校验，不改动
```

只装不校验、或只想看会做什么：

```powershell
$p = "D:\1Anewproject\dev\dsh-skills\agent-dev-workflow\scripts\install.ps1"
& $p             # 安装/更新
& $p -Uninstall  # 卸载
& $p -WhatIf     # 只预览
```

- 必须执行**【源目录】里的那份脚本**，不要执行已安装副本里的那份。
- ⚠️ 已安装副本（`<DSH_HOME>\skills\agent-dev-workflow\scripts\install.ps1`）下"源 = 目标"，
  会先把目标删掉再复制一个已不存在的源，**把 skill 整个删光**。脚本已加护栏（源=目标时直接报错），但别去踩它。
- 安装前校验 frontmatter：`name` 必须存在、**键名大小写敏感**（`Name:` 会被拒绝）、必须是**小写 kebab-case**、与安装名一致、有 `description`。安装后校验文件确实落盘。
- **校验是必须的，不是可选的**：安装目录是**副本**，改源不等于改部署。`sync.ps1` 退出码非 0 就说明两者不一致。
- 脚本支持 `powershell -File` 调用。PS 5.1 下 `param()` 默认值里的 `$PSScriptRoot` 是空的（参数绑定早于脚本作用域建立），所以定位逻辑写在脚本体里、参数默认值留空。

## 9. 反面清单（这套流程要治的病）
